## 三、日常怎么用

**所有脚本都通过 `run.sh` 调用**，它会自动切到项目目录
（18 个核心脚本靠当前目录定位文件，直接 cd 进去跑也行，但不推荐）：

```bash
./run.sh 发送层自检.py              # 改动代码后必跑：34 项自检
./run.sh 扫描回复.py --days 14      # 扫描近 14 天客户回复（只读，安全）
./run.sh 扫描退信.py                # 扫描退信并更新黑名单
./run.sh scripts/构建跟进队列.py --build
./run.sh 邮箱客户端.py test         # 测试邮箱连通性
```

⛔ **不要在本仓库注册 launchd/cron 定时任务** —— 主力机归主力机，
新机只做手动操作，避免两边同时发信、跟进表 diverge。

## 四、几条铁律（改代码前先看）

这些是从 40 天实战里攒下来的，写在 `context/workspace-workbuddy-ai/memory/` 里：

1. **分工铁律**：找客户只产交接单；写信只产正文；发送与排程归脚本。
2. **只发 A 档**：角色邮箱（`info@`/`sales@`）与 catch-all 一律暂缓，
   实测角色邮箱退信率 14.3%、具名邮箱 4.2%（差 3.4 倍）。
3. **跟进信零退信**：二次及以上发送，软退信冷却到期也仍拦截；同域曾退信则整个域不再发。
4. **排除即永久排除**：判定不可开发的公司登记在 `线索资产/永久排除名录.md`，命中即丢弃。
5. **POWER ELECTRONICS 是自家代理**，不是客户，任何名单都要排除它。
6. **发送量统计口径**：9/15、9/17、9/18、9/23、9/25、9/30 是手工批次（不走项目验证），
   报退信率时必须与项目批次分开算。
