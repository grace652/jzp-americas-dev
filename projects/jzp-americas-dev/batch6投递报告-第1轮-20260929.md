## 五、🔴 需要你决策的风险：同一队列存在两个驱动方

巡检时发现**另一会话**（`CODEBUDDY_SESSION_ID=f5e47abc-…`）也在驱动同一个 `发信队列.json`：

```
... sleep 60 && ... 定时发送.py --run --send --yes
```

两个函数的并发保护**不对等**：

| 函数 | 读队列时机 | 并发安全性 |
|---|---|---|
| `cmd_daemon` | **每封投递前重读**（`cur is None or status != pending → continue`） | ✅ 天然防重复 |
| `cmd_run` | **只在开头读一次**，之后不再复核 | ❌ 两个 `--run` 同分钟触发 → **同一封发两遍** |

**风险**：守候进程（每封前重读）与另一会话的 `--run` 若在同一分钟内命中同一封信，会**重复投递**——
对真实买家重发冷邮件会消耗发信域信誉。

**建议（本轮未擅自改动任何自动化）**：同一队列只保留一个驱动方。推荐保留本 `--daemon`（有锁 + 逐封复核），
暂停自动化 `fef370c5-956b-4853-8551-b67227e50243`（「跟进信投递看护（38封·错峰至凌晨03:30）」，
其原任务已于 09-29 04:04 收官，可停用）。
