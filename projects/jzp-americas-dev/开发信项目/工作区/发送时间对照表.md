## 核心逻辑

**目标时刻 = 对方当地 上午 9:00–10:00**（刚上班，先看邮件）

换算公式：
```
北京发信时间 = 9:00 − 对方时区偏移 + 8
```

**为什么是上午 9–10 点**：
- 刚上班，邮件排在收件箱最上面，第一眼就看到
- 还没被一天的会议和琐事淹没，有心情读完
- 太早（当地 6–7 点）邮件会沉到隔夜邮件堆里
- 太晚（当地下午）客户已经在处理别的事，你的信排在几十封之后

⚠️ **避开发送**：当地周五下午、周末、当地公共假日 —— 邮件会烂在收件箱底。

## 夏令时说明（重要）

夏令时（DST）会让时差**少 1 小时**，所以发信时间要**提前 1 小时**。

| 地区 | 夏令时起止 | 说明 |
|---|---|---|
| 北美（美/加）| 3 月第二个周日 → 11 月第一个周日 | 期间用表里"夏令"时间 |
| 欧洲 | 3 月最后周日 → 10 月最后周日 | 期间用表里"夏令"时间 |
| 澳洲（悉尼）| 10 月第一个周日 → 4 月第一个周日 | **与北半球相反** |
| 土耳其 | 全年夏令（UTC+3 固定）| 不用调 |
| 沙特/阿联酋 | 无夏令时 | 不用调 |

**记不准怎么办**：Google 搜 `time in Toronto now`，看当前当地时间，然后倒推。
或者简单点——**表格里的两个时间都发不了大错**，差 1 小时客户一样能看到。

## 怎么用

以后我交付开发信时，会在邮件信息里加一行，形如：

```
【建议发送时间】北京时间 21:00–22:00
  （安大略当地上午 9:00–10:00，客户刚上班看邮箱；
    当前为北美夏令时，冬令时请改为 22:00–23:00）
```

同时跟进表 `开发信跟进表.xlsx` 里也会记这个信息。
