# project3/scripts · 派生文件生成脚本

## 用途

`clients/INDEX.md` 是**派生文件** —— 它不是手工维护的，而是从两个源自动生成：

| 源 | 提供什么 |
|---|---|
| 工作区 `开发信跟进表.md` | 客户名 / 国家 / 买家类型 / 骨架 / 状态 / 下次跟进 |
| `project3/clients/开发信-*.md` 的批注 | 钩子（显式「钩子：」/「落点」记载）+ 产品切片 + 开场角度 |

**为什么不手工维护**：75 家客户 × 5 个维度 = 375 个字段，手工会漂移。
派生能保证 INDEX 与跟进表、与信件批注永远一致。

## 用法

```bash
# 按顺序跑（第二条依赖第一条产出的 recs.json）
python project3/scripts/gen_clients_index.py
python project3/scripts/render_clients_index.py
```

中间产物 `.workbuddy-ai/tmp/recs.json`（可随时删，重跑即再生）。

## 何时重跑

- 新增客户信件后（跟进表追加 + `clients/` 放信）
- 改了某封信的「钩子」或「落点」批注后
- 改了 `01_skill_email_writing.md` §三 钩子表里买家类型 → 钩子的对应关系后

## 提取规则（脚本逻辑）

### 钩子列

1. **显式记载优先**：信件批注里出现「钩子：」「钩子=」「**钩子**」→ 取该句并归类。
   目前 75 家里有 12 家是这样。
2. **买家类型兜底**：无显式记载时，按 `01` §三 钩子表归类：
   - 分销商 / 合作社 / 渠道 → `价格阶梯+MOQ+交期`
   - EPC → `报审 submittals`
   - 调试 / 测试专家 → `工厂测试数据`
   - 其余承包商 → `工厂测试数据+规格书`

   > ⚠️ 兜底是**近似**，不是事实记载。要精确知道某家当时用了什么，读那封信的批注。

### 产品切片列

1. **「落点」记载优先**：批注里常见的 `落点 ...` 一句 → 归类。
2. **正文产品词反推**：早期信件（1–15 号）没有「落点」批注，
   从正文里扫 `padmount` / `pole-mount` / `dry-type` / `substation transformer`
   等产品词反推。

   > ⚠️ 本列记录的是**首封实际落点**，不是对该客户的产品范围承诺。

### 开场角度列

1. **「★ 开场：」记载优先**。
2. **正文首段兜底**：跳过问候语取第一段。

### 已知缺口

`#34 Transformer Engineering Services`、`#35 Techline`、`#72 RESCO`
三家是**电话店**（零邮箱，走电话脚本），没有邮件信件，
所以它们的「产品切片」「开场角度」两列是 `—`。这是预期的，不是 bug。

## 维护注意

- **不要在 `clients/INDEX.md` 里手改客户行** —— 会被下次重跑覆盖。
- 源数据的**主文件是 `开发信跟进表.md`**，新增客户请加在那里。
- 改了脚本的归类规则后，别忘了同步 `01` §三 钩子表和 INDEX 的 §二 统计表。

## audit_project2_interface.py · 上下游接口体检

**用途**：把「找客户」（项目2）的交接单输出，与本项目的写作依赖逐字段对表，
统计到位率，找出**饿着的字段**。不是生成文件，是**体检报告**。

```bash
python project3/scripts/audit_project2_interface.py
# 换路径：
python project3/scripts/audit_project2_interface.py --project2 "D:/path/project2/buyers"
# 落盘 JSON：
python project3/scripts/audit_project2_interface.py --json report.json
```

**何时跑**：

- 项目2 **改了交接单模板或字段名**之后
- 项目2 **出了新批次**（batch4+）之后
- 本项目**新增了写作依赖字段**之后

**读报告**：

- `主干字段到位率` —— 应全部 ≥95%。**低于 95% 会列进结论区。**
- `重点标的` —— 这 5 项决定信件质量上限，**低是正常的**（它们是待改进项，
  见 `06_项目2接口对齐审计-20260923.md`）。修好之后这里应该全部变绿。

**判定方式**：关键词命中（段落标题 / 字段名 / 档位字母 / 三态标记），
不做语义理解 → **宁可宽松也不误报**。所以"到位"只代表"写了这段"，
不代表内容质量。内容质量仍须人工抽读。
