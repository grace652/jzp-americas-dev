# project1 · 客户推导

> 本项目用于：**根据公司已开发客户名单和产品信息，推导同行业同类型的候选新客户。**
>
> 🎯 **本项目核心动作只有一个：判断一家公司「是不是我们的目标客户」。**
> **不负责找联系人、不负责找邮箱** —— 那是项目2 的职责。本项目只需要回答：
> 「这家公司符合我们的客户画像吗？凭什么这么判断？证据在哪？」

## 二、文件分层原则

| 层 | 文件 | 改动纪律 |
|---|---|---|
| **00** | `00_data_source_setup.md` | 🔴 **数据源契约（路径 / 列名 / 排重规则 / 失效判定）。路径或列名变了必须改这里** |
| **00b** | `00_readiness_check.py` | ✅ 开工前置检查脚本。读不到文件 / 文件太旧 / 列名变了 → 直接报错停止 |
| **01** | `01_core_rules.md` | 🔴 **核心逻辑：目标客户判定标准 + 红线。改动前必须列出改动点等用户确认** |
| **02** | `02_execution_steps.md` | 🔴 **执行步骤 + 输出字段（跨项目契约）。字段名与顺序不能擅改** |
| **03** | `03_profile_pattern_notes.md` | 📝 **画像模式参考**。辅助锚点，**不是数据源**。含最后更新日期，过期需重核 |
| **04** | `04_lessons_learned.md` | 📝 **持续追加** 踩坑记录 |

> 🔴 **核心工作流一句话**：
> **先定画像（谁像我们现在的客户）→ 再判归属（是不是目标客户）→ 最后排重（有没有碰过）。**
> 三步缺一不可；**排重不是可选步骤**，漏一家 = 后续项目2 白做一轮。

## 三、跨项目契约（不可擅自更改）

- **本项目的输出 = 项目2 的输入**。
- 项目2 已在 `project2/03_input_contract_from_project1.md` 逐字登记本项目的输出字段：

```
公司名 | 国家/地区 | 行业 | 公司规模 | 产品线 | 来源链接 | 推导理由
```

> 🔴 **字段名、顺序、数量都不能改。** 若确需变更（增删/改名/换序/换分隔符），必须先列出改动点等用户确认，
> 然后**同步更新** `project2/03_input_contract_from_project1.md` 与 `project2/01_execution_steps.md`，
> 并检查是否要告知项目3。**改一侧不改另一侧 = 项目2 读取失败或字段错位。**
>
> ℹ️ **本字段表中没有邮箱和联系人 —— 这是刻意的**，与"本项目不负责找联系人"的职责边界一致。
